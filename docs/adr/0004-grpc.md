# 4. gRPC with Protobuf for the service APIs

Status: accepted (2026-11-25)

## Context

Three things have to agree on data shapes: the command API, the query API, and
the events in Kafka. The events are read by Go (command service, projector)
and TypeScript (notifier), and must stay readable forever (ADR 3). The clients
are other services and internal tools, not browsers.

## Decision

- **Protobuf is the single schema** for both APIs and events
  (`proto/pipeline/v1`). Generated Go and TypeScript code is committed, and CI
  fails if it is stale.
- **gRPC for the command and query APIs**, split into two services
  (`PipelineCommandService`, `PipelineQueryService`) so each side can be
  deployed, scaled and secured separately.
- **`buf lint` and `buf breaking` run in CI.** A renumbered field or renamed
  RPC fails the build. For events that is a data-integrity guarantee, not just
  style: an event written today has to decode in five years.
- **Errors use gRPC status codes with fixed meanings** (`FAILED_PRECONDITION`
  for a disallowed stage move, `ABORTED` for a version conflict that is safe to
  retry, `ALREADY_EXISTS` for a reused idempotency key). Clients can decide
  whether to retry from the code alone.
- **Deadlines are enforced server-side** (the `grpcx.Deadline` interceptor caps
  every request), so a slow dependency can't hold a handler indefinitely.

## Alternatives considered

- **REST + JSON with OpenAPI.** Easier to call with `curl` and from browsers.
  But the events still need a compact, evolvable binary format, so there would
  be two schema languages to keep in sync. JSON's field-name-based evolution is
  also easier to break silently.
- **Avro + schema registry for the events.** The standard Kafka answer, with
  compatibility checks at produce time. It adds a registry to run, and gRPC
  would still need Protobuf. One schema language won.

## Consequences

- One `.proto` change updates Go, TypeScript and the docs, and CI checks
  compatibility.
- `grpcurl` and server reflection replace `curl` for manual testing. That is
  slightly less convenient, and the README shows the commands.
- Browsers can't call gRPC directly. A public frontend would need a gateway
  (gRPC-Web, Connect, or the GraphQL gateway in the stretch goals).
- Protobuf only guarantees wire compatibility. A field whose meaning changes
  passes `buf breaking`, so semantic changes still need review.
